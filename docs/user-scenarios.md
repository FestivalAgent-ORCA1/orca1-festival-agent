# ORCA 사용자 이용 시나리오

2026-11-19 · FE1 김건우 작성 · develop `843770e`의 화면·서버 코드를 기준으로 정리한 팀 검토안

사용자가 **갈 축제를 발견하고 → 하루 일정을 만들고 → 저장해 다시 이용하고 → 경험을 나누는 과정**을 목적별로 정리했습니다. 아래 기대 결과는 시연·통합 점검의 기준이며, 실제 서버에서 모든 과정을 검증했다는 뜻은 아닙니다.

## 목적별 흐름

| 번호 | 사용자 목적 | 진입과 주요 흐름 | 완료 결과 | 로그인 |
| --- | --- | --- | --- | --- |
| S1 | 갈 만한 축제를 직접 찾고 싶다 | 홈/축제 찾기 → 이름·지역·분위기 선택 → 목록 → 미리 보기/상세 | 날짜·장소·운영 시간·요금을 확인하고 갈 축제를 고른다 | 조회는 불필요 |
| S2 | 내 취향에 맞는 축제를 추천받고 싶다 | 가입/로그인 → 첫 설정 → 홈 맞춤 추천 → 축제 상세 | 추천 이유를 보고 관심 있는 축제를 고른다 | 필요 |
| S3 | 축제와 주변 장소를 묶어 하루를 계획하고 싶다 | 상세의 ‘이 축제로 일정 짜기’ 또는 AI 일정 → 방문일·시간 대화 → 시간표·지도 → 저장 | 축제·주변 장소·이동 시간이 담긴 일정을 내 일정에 저장한다 | 생성은 불필요, 저장은 필요 |

| S5 | 관심 있는 축제를 모으고 시작 소식을 확인하고 싶다 | 카드/상세의 하트 → 나의 티켓 → 알림함 → 축제 상세 | 찜한 축제를 다시 찾고, 조건에 맞는 알림을 확인한다 | 필요 |
| S6 | 방문 후기를 읽고 경험을 나누고 싶다 | 커뮤니티 → 글 상세 → 댓글 / 글쓰기 → 등록 | 후기·팁을 읽거나 자신의 글과 댓글을 남긴다 | 읽기는 불필요, 작성은 필요 |

## S1. 갈 만한 축제 직접 찾기

**상황:** 주말에 외출하고 싶지만 어느 축제에 갈지는 정하지 않았다.

1. 홈 또는 상단 ‘축제 찾기’로 들어간다.
2. 축제 이름이나 지역을 고른다. 필요하면 ‘반짝이는 밤’·‘맛있는 하루’ 분위기를 선택한다.
3. 시작일순·종료일순·이름순으로 정렬하거나 다음 페이지를 둘러본다.
4. 사진을 눌러 미리 보기를 열고, ‘축제 더 구경하기’ 또는 카드의 ‘구경하기’로 상세에 들어간다.
5. 날짜·장소·운영 시간·요금·소개를 확인한다. 공식 주소가 있는 축제는 ‘공식 안내 보기’로 최신 안내를 확인한다.
6. 비슷한 축제를 더 보거나 S3의 일정 만들기로 이어간다.

**기대 결과:** 고른 검색 조건에 맞는 축제가 표시되고, 목록에서 선택한 축제와 상세의 축제가 일치한다. 결과가 없으면 조건을 초기화해 다시 탐색한다.

## S2. 내 취향으로 축제 추천받기

**상황:** 여러 축제를 일일이 비교하기보다 자신의 취향에 가까운 후보를 먼저 보고 싶다.

1. 이메일·비밀번호·닉네임으로 가입하거나 기존 계정으로 로그인한다.
2. 첫 설정에서 연령대와 관심사 1~5개를 고른다. 선호 지역은 최대 3개이며, 고르지 않으면 전국을 대상으로 한다.
3. 설정을 저장하고 홈의 ‘당신의 취향에 가까운 곳’을 확인한다.
4. 추천 이유와 축제 정보를 비교하고 상세로 이동한다.
5. 관심 있는 축제를 찜하거나 S3으로 이어간다. 취향을 바꾸려면 ‘내 정보 → 내 주말 취향 → 바꾸기’를 이용한다.

**기대 결과:** 설정한 취향과 찜 정보를 활용한 추천을 확인한다. 첫 설정을 완료하지 않은 계정에는 추천 영역을 숨기며, 설정 후 홈으로 돌아와 확인한다. 추천 결과가 없으면 일반 축제 목록으로 탐색을 계속한다.

## S3. 하루 일정 생성하고 저장하기

**상황:** 갈 축제는 골랐지만 식사·카페·주변 관광까지 포함한 순서와 시간을 정하기 어렵다.

1. 축제 상세에서 ‘이 축제로 일정 짜기’를 누른다. 선택한 축제를 유지한 채 AI 일정 화면으로 이동한다.
2. 축제 기간 안의 방문일과 원하는 시간대를 말한다. 예: ‘11월 21일 오전 11시부터 오후 6시까지, 카페도 넣어줘.’ 날짜는 시연할 축제에 맞게 바꾼다.
3. 정보가 부족하면 AI의 추가 질문에 답한다. AI 일정 메뉴로 바로 들어왔다면 축제를 먼저 추천받거나 축제명을 알려준다.
4. 시간표에서 방문 순서·체류 시간·이동 시간과 안내 문구를 확인하고, 지도에서 장소를 확인한다.
5. 필요하면 ‘카페를 추가해줘’처럼 대화로 변경을 요청하고 새 시간표를 확인한다.
6. 저장 버튼을 누르고 일정 이름을 정한다. 비로그인 상태면 먼저 로그인한다. 같은 브라우저 탭에서 로그인 후 돌아오면 보관된 시간표에서 저장 버튼을 다시 누른다.
7. ‘내 일정’에서 저장된 이름·날짜·축제를 확인한다.

**기대 결과:** 화면에서 확인한 시간표가 내 계정의 일정으로 저장된다. 대화 자체는 저장되지 않으므로 새로고침 전에 시간표를 저장한다. 지도 설정이 없으면 지도 안내와 장소 목록으로 확인하며, 실제 지도 표시는 별도로 점검한다.

## S4. 저장한 일정 조회·변경하기

**상황:** 이미 저장한 계획의 출발 시간이나 들를 장소가 바뀌었다.

1. 로그인 후 ‘내 일정’에서 저장한 일정을 선택한다.
2. 일정 상세에서 시간표와 지도를 확인한 뒤 ‘다시 계산하기’를 누른다.
3. 이름·방문일·시작/종료 시각·주변 장소를 변경하고 다시 계산한다.
4. 새 시간표와 안내를 검토한다. 마음에 들지 않으면 ‘원래대로’ 또는 취소를 선택한다.
5. ‘이 시간표로 저장’을 누른 뒤 목록에서 해당 일정을 다시 열어 변경 내용을 확인한다.

**기대 결과:** 다시 계산한 내용은 확인 후 저장해야 반영된다. 잘못된 시간 범위나 축제 기간 밖의 날짜는 안내를 보고 수정한다. 삭제는 별도 확인 창에서 결정한다.

## S5. 찜한 축제와 알림 확인하기

**상황:** 바로 일정을 만들지는 않지만 가고 싶은 축제를 모아 두고 행사 시작 전에 다시 확인하고 싶다.

1. 로그인한 상태에서 목록·미리 보기·상세의 하트를 누른다. 비로그인이면 로그인 안내를 확인하고, 로그인 후 다시 찜한다.
2. ‘나의 티켓’에서 찜한 축제를 확인하고 상세로 다시 들어간다. 하트를 다시 누르면 찜을 해제할 수 있다.
3. ‘내 정보 → 알림함’에서 도착한 축제 소식을 확인한다.
4. 알림을 누르면 읽음 상태로 바뀌고 해당 축제 상세로 이동한다. 필요하면 ‘모두 읽음’을 이용한다.

**기대 결과:** 같은 축제의 찜 상태가 목록·상세·나의 티켓에서 일치한다. 알림은 찜 직후 즉시 생성되는 것이 아니라, 매일 실행 작업이 시작 7일 전·1일 전·당일 또는 종료 다음 날 조건을 확인해 만든다. 종료 후에는 조건에 맞는 비슷한 축제가 있을 때 추천 알림을 만든다. 사이트 알림함을 이용하며 이메일·휴대폰 푸시 발송은 이 시나리오에 포함하지 않는다.

## S6. 후기·팁 읽고 작성하기

**상황:** 방문 전에 다른 사람의 경험을 참고하거나, 다녀온 뒤 유용한 정보를 남기고 싶다.

1. ‘커뮤니티’에서 글 목록과 상세를 읽는다.
2. 글쓰기를 누른다. 비로그인 상태면 로그인 후 작성 화면으로 돌아온다.
3. 제목과 내용을 작성하고 ‘올리기’를 누른다. 특정 축제가 연결된 작성 화면에서는 해당 축제와 함께 등록된다.
4. 등록한 글 상세에서 내용과 작성자를 확인한다.
5. 다른 글에 댓글을 남기거나 자신의 글을 수정한다. 자신의 글은 확인 후 삭제할 수 있고, 자신의 댓글도 삭제할 수 있다.

**기대 결과:** 등록한 글과 댓글을 다시 읽을 수 있고, 자신의 글에만 수정·삭제 동작이 제공된다.

## 팀 시연 순서와 준비

| 순서 | 보여줄 흐름 | 준비·확인할 것 |
| --- | --- | --- |
| 1 | 비로그인 축제 탐색 → 미리 보기 → 상세 | API 모드, 서버 응답, 실제 축제·사진·날짜. 12개 목록의 두 번째 줄 이후도 같은 카드 장식이 적용되는지 확인 |
| 2 | 가입/로그인 → 취향 설정 → 홈 맞춤 추천 | 시연 계정은 담당자가 준비. 추천 후보가 부족하면 일반 목록으로 이어가기 |
| 3 | 선택한 축제 → AI 대화 → 시간표·지도 → 저장 | 축제 기간 안의 방문일, AI 사용량·서버 설정, 배포 도메인의 지도 허용 설정 |
| 4 | 내 일정 → 다시 계산 → 저장 → 다시 열기 | 시연 계정 본인의 일정 사용 |
| 5 | 찜 → 나의 티켓 → 알림함 | 알림 시연용 데이터와 자동 실행 상태는 BE2/BE1에게 확인. 찜하자마자 알림이 생긴다고 설명하지 않기 |
| 6 | 커뮤니티 → 글/댓글 작성 → 확인 | 시연용 글임을 표시하고 본인 데이터만 사용 |

### 담당별 확인 요청

- **FE1 건우:** 홈·목록·상세·찜, 카드 배치와 공통 디자인, 이 문서 정리.
- **FE2 규원:** 선택한 축제가 채팅으로 전달되는지, 일정 생성·저장·재계산, 지도와 시간표 연결.
- **FE3 혜정:** 가입·로그인·첫 설정·복귀, 커뮤니티·알림 화면, 실제 API 모드 배포.
- **BE1 소현 / BE2 민경:** 추천·AI·주변 장소·이동 시간, 저장·권한·찜·알림 API, 시연용 계정·알림 데이터와 자동 실행 상태.
