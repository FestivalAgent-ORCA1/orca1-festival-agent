## 한 일

1. **Vercel 환경 변수 입력 → 다시 배포** (Production)
   - `VITE_DATA_MODE=api`
   - `VITE_API_BASE_URL=https://orca1-festival-agent.onrender.com`
   - 배포된 코드에 Render 주소가 들어간 것과, 축제 목록이 실제 데이터로 뜨는 것을 확인했습니다.
2. **CORS 확인**: 배포 주소(`https://orca1-festival-agent-frontend.vercel.app`)에서 보내는 요청을 서버가 허용하는지 직접 확인했습니다. 오류 없음.
   - GET `/api/festivals`, `/api/posts`
   - 사전 요청(OPTIONS): `/api/auth/signup`, `/api/posts`, `/api/users/me/preferences`, `/api/notifications/read-all`
   - 로컬 `http://127.0.0.1:5173`, `http://localhost:5173`도 허용되어 있습니다.
3. **실제 서버와 응답 모양 비교** (Render의 `/openapi.json` 기준): 회원·내 정보·커뮤니티·알림 API의 주소, 응답 필드, 오류 형식(`{code, message}`)이 프론트 코드와 일치합니다.

## 고친 것: 첫 설정의 연령대 필수

- 서버 `PreferencesRequest.age_group`은 **필수 문자열**입니다 (`docs/db-schema.md`: NULL은 온보딩 전에만).
- 프론트 첫 설정 화면은 "선택하지 않을게요"로 `null`을 보낼 수 있어서, 실제 서버에서는 `422 VALIDATION_ERROR`가 납니다. 예시 모드에서는 드러나지 않던 차이입니다.
- `OnboardingPage.jsx`: 연령대를 꼭 고르게 변경. `demoAuth.js`도 서버처럼 연령대가 없으면 422. `tests/auth.test.js`에 테스트 1개 추가.
