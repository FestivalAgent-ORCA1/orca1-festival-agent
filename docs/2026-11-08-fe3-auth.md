# 2026-11-08 · FE3 로그인·첫 설정·하단 메뉴

PR #1(FE1)이 develop에 머지된 뒤, 그 위에 FE3 담당인 로그인 흐름과 모바일 하단 메뉴를 연결했습니다.

## 준비

- Node.js 26.13.0, pnpm 11.25.0 설치. Node 25부터 corepack이 빠져 있어 `npm install -g pnpm@11.25.0`으로 설치했습니다.
- `git pull origin develop` 중 `.gitignore`가 충돌했습니다. develop 쪽 내용(`backend/certs/` 포함)으로 해결했습니다.

## 추가한 것

| 커밋 | 내용 |
| --- | --- |
| 로그인 상태 관리 | `api/auth.js`, `api/users.js`(api-spec 2장), `contexts/AuthContext.jsx`, 예시 모드용 `api/demoAuth.js` |
| 로그인·가입·첫 설정 | `/login`, `/signup`, `/onboarding` 페이지, `styles/auth.css`, 연령대 목록 `data/preferences.js` |
| 하단 메뉴 | `components/layout/BottomNav.jsx`, `styles/layout.css`, `Icon.jsx`에 home·chat·community·user 아이콘 추가 |

### FE1과 맞춘 약속 (frontend/README.md "FE3에게 연결을 부탁할 부분")

- 토큰은 `localStorage.access_token`에 저장하고, 로그인·로그아웃 뒤 `orca:auth-changed` 이벤트를 보냅니다. 찜 목록이 이 이벤트로 다시 읽힙니다.
- 로그인 후 돌아갈 주소(`?redirect=`)는 `/`로 시작하는 내부 경로만 허용합니다. `/login`·`/signup`·`/onboarding`으로 돌아가는 경우는 무한 이동을 막기 위해 `/`로 보냅니다.
- `router/index.jsx`의 `/login` 자리를 실제 `LoginPage`로 교체했습니다.

### 동작

- 가입 → 첫 설정 → 원래 보던 페이지.
- 로그인 → `user.onboarded`가 `false`면 첫 설정, 아니면 원래 보던 페이지.
- 첫 설정: 연령대(선택), 지역 0~3개, 관심사 1~5개(docs/tags.md 기준).
- 헤더: 로그인 전 **로그인**, 로그인 후 **로그아웃** 버튼.
- 620px 이하: 하단 메뉴(홈·축제·AI 채팅·커뮤니티·내 정보/로그인)를 보여주고 헤더의 로그인 버튼은 숨깁니다.

### 예시(mock) 모드

백엔드(BE2) 로그인 API가 아직 없어 예시 모드에서 가짜 계정을 씁니다.

- 계정은 이 브라우저의 `orca:demo:users:v1`에 저장합니다. **비밀번호는 저장하지 않으며**, 가입한 이메일 + 8자 이상의 아무 비밀번호로 로그인됩니다.
- api-spec의 입력 규칙(비밀번호 8자 이상, 닉네임 2~15자, 이메일 중복 409, 관심사 1~5개, 지역 0~3개)을 그대로 따릅니다.
